## 宿題

- 取り組んだレベル：実装
- やったこと：
  - `app/ask.py` に `--chat` オプションを追加し、会話履歴を保ったまま続けて質問できるようにした
    （例: `uv run python -m app.ask --chat "LoRAとは何ですか？"`）
  - google-genai SDK の Chat API（`client.chats.create()` → `chat.send_message()`）を使い、履歴の保持を SDK に任せた
  - 空行・`exit`・Ctrl-D で終了する。API エラーが出ても終了せず、続けて質問できる
  - 回答のたびに `[履歴] N 件` を表示し、履歴が増えていくのを見えるようにした
  - API キーなしで動くテスト `tests/test_ask.py` を追加した（API の代わりに偽物の `generate_content` を使う）
- 結果：
  - テスト 3 件が通った（Codespaces の `uv run pytest -q` でも確認）
  - 2 回目に送る `contents` が `[質問1, 回答1, 質問2]` になっていることを、テストで確認した
  - Codespaces の実 API（gemini-3.5-flash-lite）で、履歴あり・なしを比べた

    | 1 回目 | 2 回目 | 履歴なし（`--chat` なし、別々に実行） | 履歴あり（`--chat`） |
    |---|---|---|---|
    | 餃子とは？ | 何をつけて食べる？ | 「何について」が分からないと聞き返された | 醤油・酢・ラー油など、餃子のタレを答えた |

- 気づき・疑問：
  - Gemini API は会話を覚えないので、続けて質問するには過去の質問と回答を毎回すべて送り直す必要がある
  - そのため、会話が長くなるほど入力トークンが増える。長い会話では、古い履歴を削るか要約する必要がありそう
  - 失敗したやり取りは SDK が履歴に残さないので、同じ質問を入力し直せばやり直せる
  - 最初の実装では、関数の中で作った `genai.Client` が関数を抜けた時点で破棄され、接続が閉じていた。
    そのため、送信時に `RuntimeError: Cannot send a request, as the client has been closed.` になった。
    `main()` で `with genai.Client(...)` を使い、会話中は Client を開いたままにして直した
  - API を偽物に差し替えたテストでは、この不具合は見つからなかった。
    本物の Client を通して接続が開いているかを確かめるテストを足し、再発を防いだ
